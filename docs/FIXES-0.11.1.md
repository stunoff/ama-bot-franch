# Исправления 0.11.1

| Аудит настройки | Изменение |
|---|---|
| S01 | init-admin использует существующий аккаунт/человека и совместимую управляющую привязку; --recover восстанавливает маршрут действующего администратора без дубликатов и переноса истории. |
| S02 | Блокировка bootstrap учитывает текущий bot_id, срок, системную область и доступный аккаунт администратора. |
| S03 | Probe проверяет версию и адрес до отправки; устаревший тест отменяется. |
| S04 | replace_binding обновляет и версионирует зависимые Record(kind=route), включая опубликованные маршруты новых обращений. |
| S05 | Подтверждение probe объединено для worker, CLI и интерфейсной сверки. Старый адрес/версия не подтверждает новый чат. |
| S06 | Токены маскируются в HTTP-логах и диагностике; перехваченные ошибки регистрации/bootstrap не печатают URL с токеном. |
| S07 | Для активации клиентского маршрута проверяется пригодное назначение ФП нужного бота/области и активный аккаунт соответствующей платформы. |
| S08 | register-webhooks отклоняет отсутствие токенов и некорректный URL/секрет, показывает безопасную причину отказа API. |
| S09 | При публикации проверяются внутренний маршрут, область, календарь, профиль исполнителя, роли/аккаунты принимающего; preflight проверяет те же ограничения. |

Экран постановки теста в очередь прямо сообщает, что чат ещё не подключён, и даёт кнопку обновления статуса.

Регрессионные проверки: tests/test_setup.py и дополненная проверка интерфейса в tests/test_ui.py. Штатный запрет повторного init-admin без --recover сохранён. Схема БД и старые миграции не менялись.

Живые Telegram/MAX, фактические группы заказчика и его сервер не проверялись этим патчем. Утверждение о полном выполнении всех критериев ТЗ не делается. Инструкция: UPGRADE-0.11.1.md.
