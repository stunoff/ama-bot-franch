# Ознакомление и материалы · 0.8.0

## Что заполнить владельцу

Владелец ещё не предоставил действующие ссылки, видеоматериалы и опубликованный короткий курс КЦ. Они не заменены вымышленными URL. Реестр содержит 85 требований, извлечённых из исходного ТЗ, с повторным использованием постоянных ключей по одинаковому назначению. Обязательность и область каждой ссылки подтверждает владелец. Общий курс из 143 исходных карточек сохранён; его ранее назначенные снимки миграция не меняет.

Администратор: `/af_settings` → материалы и база знаний → создать/изменить материал. Укажите название, тип, безопасный HTTPS-URL, аудиторию, бренд/предприятие при необходимости, раздел, назначение и владельца содержания. Для публикации нужны подтверждение содержания, дата проверки и четыре пункта: открывается; права нужной аудитории; файл существует; название соответствует назначению. Это ручная проверка владельца: бот не объявляет внешний URL рабочим на основании одного HTTP 200 и не запрашивает секреты.

В рабочем меню куратора «Ознакомление ФП» → «Готовность контента» виден реестр незаполненного. Администратор может через предпросмотр подготовить черновики материалов; в них нет URL, владельца и автоматической публикации. Повтор не создаёт дубликаты. Затем владелец заполняет реальные записи и связывает их стабильные ключи с обязательными материалами карточек. Полная программа из 143 карточек не публикуется заново без настройки материалов разделов 0–11. Действующая ранее опубликованная версия продолжает работать до осознанного переключения.

Короткий курс КЦ публикуется отдельно с ключом `call_center` и утверждёнными карточками. Применимость берётся по конкретному предприятию; техническая готовность КЦ ей не подменяется. Общий курс из-за КЦ не повторяется.

## Персональный маршрут

`/learning` в клиентском чате → продолжить общую базу или доступный КЦ. `/training` также открывает новый интерфейс. Куратор в сопровождении через `/learning` назначает конкретному ФП ознакомление в проверенном клиентском чате или фиксирует подтверждённое ранее ознакомление. Для наследования нужны основание и известная версия; сохраняется решение куратора, а не новая дата личного прохождения ФП. Можно продолжить только обязательные обновления при таком подтверждении прежней базы.

Один и тот же человек использует общий результат в нескольких брендах/предприятиях. Новый человек не получает чужое прохождение вместе с ролью. Замена подтверждённого аккаунта при сохранении person_id не сбрасывает прогресс. Наблюдатель не подтверждает карточки за ФП.

На карточке: «Назад», «Понятно, дальше», материалы карточки, «Продолжить позже». На границе раздела — отдельное «Завершить раздел». После всех разделов — явное «Ознакомился / завершить ознакомление». Здесь нет оценок, экзаменов и пересдач. Повторный просмотр сохраняет прежнее подтверждение. Ссылка открывает текущую разрешённую редакцию справочника; переход по ссылке не объявляется доказательством прочтения внешнего документа.

Если обязательный материал отсутствует или недоступен по роли/области, карточка показывает техническое ожидание, не засчитывает завершение и позволяет сообщить о проблеме. По одной проблеме ссылки используется связанная техническая работа, без новой полной анкеты. Восстановление ссылки/проверенная замена не подтверждает ознакомление за пользователя.

## База знаний и версии

`/knowledge` показывает только разрешённые действующие материалы. Общая база с режимом «После общего ознакомления» открывается после подтверждения; материалы текущего раздела доступны по ходу обучения. Брендовая база зависит от действующей связи бренда, КЦ — от подтверждённого обслуживания. В общем брендовом чате с несколькими адресами можно выбрать предприятие. Материалы другого адреса/бренда и внутреннего контура не подставляются.

У назначения постоянный ключ. Публикация хранит отдельный неизменяемый снимок редакции. При выдаче ссылки записывается версия и URL, а подтверждённая доставка хранится отдельно; запись в очереди не означает доставку или прочтение. Изменившаяся до отправки редакция отменяет устаревшую выдачу.

Редакционная правка или смена URL не обнуляет персональный курс. Для изменения обязательного процесса, роли, безопасности или иного действия ФП владелец выбирает «Существенное обновление», основание и отдельные карточки изменений. Создаётся короткое персональное назначение только затронутым пользователям; можно ограничить бренды. Прежний курс и его даты сохраняются. Изменение материала также создаёт отдельное ознакомление его затронутым пользователям. Перед новым внутренним открытием учитываются незавершённые обязательные обновления.

## Напоминания и контроль

Для не начатого назначения отсчёт идёт от подтверждённой доставки. Для незавершённого маршрута — от последнего содержательного действия. Открытие меню не считается продвижением. После 2 календарных дней бездействия возможно первое мягкое напоминание; ещё через 3 календарных дня после его подтверждённой доставки — второе. После двух обычных напоминаний по причине создаётся контроль куратора, ежедневного продолжения рассылки нет. Failed/uncertain не запускает следующий интервал. Для uncertain нужна явная сверка доставки через диагностику.

Каждое автоматическое сообщение использует согласованное окно партнёра и его часовой пояс. Без настройки окна создаётся контроль куратора. Куратор может через карточку прогресса согласовать персональную будущую дату с причиной — она имеет приоритет. Содержательное действие отменяет старую очередь и сохраняет место. Технически недоступный обязательный материал приостанавливает только зависимый таймер; при восстановлении учитывается время паузы. Другие независимые назначения продолжаются.

По подтверждённой плановой дате внутреннего открытия действуют D−7, D−3, D−1. Выбирается ближайший актуальный порог, без рассылки всех пропущенных стадий задним числом; D−1 обозначает блокер допуска. Незавершённое обучение учитывается отдельно от технической/маркетинговой готовности. Перенос плановой даты отменяет устаревшую отправку. В одном общем маршруте пользователя используется назначенный основной чат, без дублирования по брендам.

## Замена и архивация

В карточке материала администратор выбирает «Замена / техническое ожидание». Предпросмотр показывает активные зависимости курсов и работ. Можно указать опубликованный проверенный ключ замены с совместимой областью/аудиторией либо зафиксировать техническое ожидание с ответственным владельцем. Поле URL не заменяется случайной папкой. Старые уроки продолжают использовать стабильный ключ; история старой выдачи не переписывается.

Без рабочего обязательного материала завершение и зависимые напоминания приостанавливаются. В интерфейсе видна причина, а куратор видит технический блокер. Архивация активного курса/маршрута остаётся защищённой отдельным анализом их зависимостей; новый workflow относится к материалам. Внешние права папок сами не отзываются — владелец проверяет их отдельно.

Период повторной проверки ссылки задаётся в карточке материала. Напоминание требует повторного ручного чек-листа; сетевые запросы к произвольным пользовательским адресам не выполняются. Живые URL, права внешних папок, Telegram/MAX и финальный контент требуют приёмки владельцем на инфраструктуре заказчика.
