# Эксплуатация и приёмка · 0.10.0

## Настройка владельцем

В настройках → «Материалы и сообщения» → «Хранение, доступ и резервирование» опубликуйте одну утверждённую политику: место хранения, ответственного за доступ, получателя ошибок, основание и срок хранения, допустимые расширения/размер, предельный возраст копии и период проверки восстановления. Значения не придуманы программой. Лимит не может превышать `MAX_FILE_BYTES` адаптера. Публикация политики не удаляет исторические файлы: удаление доказательств с зависимостями и правовыми ограничениями требует отдельной проверки владельцем. До утверждения политики проверка готовности блокирует массовый запуск.

Реальные ссылки из пункта 7, курс КЦ, реквизиты и реальные роли/маршруты тоже должны быть заполнены. Черновики материалов не являются опубликованной базой.

## Проверка готовности

В управляющей теме: `/af_settings` → «Эксплуатация и приёмка» → «Проверить готовность». Отчёт не выводит токены, содержимое сообщений или сырые БД. На сервере:

```bash
cd /opt/franch-bot
docker compose exec -T api python -m ama.ops_cli preflight
```

Проверяются миграция/таблицы, активные маршруты и назначения, опубликованные настройки/владельцы, незаполненные материалы, сбои и неопределённые доставки, наличие файлов, политика хранения, копии/проверки восстановления и свидетельства живой приёмки. Это проверка условий запуска; она не заменяет содержательную оценку документов человеком.

## Резервирование

Копии хранятся **вне каталога проекта и файлового тома**, с ограничением доступа. Пример `/var/backups/ama` — оператор выбирает действующее защищённое хранилище сам. Копии содержат персональные данные и секреты из БД, их нельзя отправлять в чат. Для удалённого хранения используйте утверждённое шифрование и контроль доступа вашего инфраструктурного провайдера; ключи не помещайте в общие чаты.

В настройках можно запросить копию или проверку восстановления успешной копии. Запрос остаётся в очереди до запуска операторского runner на Docker-хосте. Docker-сокет боту не передаётся, общая тема не получает право выполнять произвольную shell-команду.

Запустить одно задание из очереди:

```bash
cd /opt/franch-bot
python3 scripts/operations-runner.py --backup-root /var/backups/ama
```

Создать запрос копии и выполнить одно доступное задание:

```bash
python3 scripts/operations-runner.py --backup-root /var/backups/ama --request-backup
```

Либо `scripts/backup.sh /var/backups/ama`. Новый формат: отдельный каталог по ID задания, `mysql.sql.gz`, `files.tar.gz`, `manifest.json`. Существующая копия не перезаписывается. На время согласованного снимка останавливаются только работающие `api`/`worker`; после процедуры возобновляются только те, которые работали до неё. Дамп и файлы сравниваются с повторным снимком до запуска записи. Манифест фиксирует число строк и SHA-256 каждой таблицы, перечень/размер/хеш каждого файла, версию и миграцию. Неуспех оставляет видимый статус/частичный каталог, а не ложную успешную копию.

Для автоматической обработки разрешённых запросов оператор может запускать runner через свой service manager с `--loop`; он опрашивает очередь раз в 30 секунд. Одновременно допускается только одна обслуживающая процедура. Конфигурация расписания и учётная запись хоста утверждаются инфраструктурным владельцем. Отдельного привилегированного контейнера с Docker-сокетом в Compose нет.

## Изолированная проверка восстановления

Возьмите ID успешной копии в журнале:

```bash
python3 scripts/operations-runner.py --backup-root /var/backups/ama --verify-backup ID_КОПИИ
```

Runner сначала проверяет контрольные суммы обоих архивов. Затем создаёт контейнер MySQL с тем же образом, отдельные временные тома БД/файлов и случайный пароль. Порты не публикуются, сеть MySQL — `none`; проверяющий контейнер приложения использует его изолированное сетевое пространство. Рабочие тома и БД не подключаются. Worker не запускается, исходящие сообщения не отправляются. После импорта сравниваются **все** таблицы и файлы со снимком копии; несовпадение считается ошибкой. Временные ресурсы процедуры удаляются по собственным уникальным именам, пользовательские тома не удаляются.

Нужно свободное место для тестовой БД/файлов и доступный образ MySQL. Архив файлов допускает только обычные файлы под `files/`, без ссылок, обхода каталогов, дубликатов и превышения объявленного объёма. Успешная проверка восстанавливаемости не является разрешением заменить рабочую БД.

При аварийном обрыве runner задание остаётся `running`: нельзя автоматически запускать ещё одну копию вслепую. Оператор проверяет процессы/частичные каталоги/ресурсы и после устранения причины может отметить неуспех:

```bash
docker compose run --rm --no-deps -T --entrypoint python api -m ama.ops_cli reconcile ID_ЗАДАНИЯ --failed --reason 'Проверено оператором; процедура остановлена, причина устранена'
```

## Реальная приёмка П01–П68

Отдельная проверка API мессенджеров только читает состояние и не отправляет сообщения:

```bash
docker compose exec -T api python -m ama.probe --platform telegram --check-chats
docker compose exec -T api python -m ama.probe --platform max --check-chats
```

Проверяются API бота, webhook/подписка, доступ к настроенным чатам, права создания тем Telegram. Ответы скрывают токены. Ошибка webhook может оставаться в Telegram как прежняя: сверяйте дату, очереди, реальный `/start` и текущие логи. Полный пользовательский сценарий probe не объявляет пройденным.

Создайте шаблон для приёмки текущей конфигурации:

```bash
umask 077
docker compose exec -T api python -m ama.ops_cli acceptance-template > acceptance-local.json
```

Выполните применимые П01–П68 из `acceptance.csv` на тестовых людях/предприятиях. В строках укажите `passed`, `failed` или `not_applicable`, реального исполнителя, фактическое время с часовым поясом (`2026-11-19T18:00:00+03:00` — пример формата) и ссылку/ID защищённого протокола. Неприменимость требует причины. Неотработанные строки остаются `pending`. Скрытые токены, переписку клиентов и реальные базы в JSON не помещайте.

```bash
docker compose cp acceptance-local.json api:/tmp/acceptance-local.json
docker compose exec -T api python -m ama.ops_cli acceptance-import /tmp/acceptance-local.json
docker compose exec -T api python -m ama.ops_cli preflight
```

Запись — явное свидетельство оператора, не автоматическая имитация живого теста. Новое отрицательное свидетельство отменяет прежний зачёт в том же сценарии. Изменение версии или существенной конфигурации требует нового шаблона; исторические свидетельства сохраняются. Требуются отдельные проверки Telegram/MAX, CDN файлов MAX, участников/тем, переноса аккаунтов, восстановления и отсутствия повторных отправок после сбоя. Неиспользуемую платформу не включают фиктивно.
