# Обновление 0.7/0.8/0.9 → 0.10.0

Выпуск включает все предыдущие этапы, отправку выбранных внутренних материалов клиенту и эксплуатационный контур. Сохраните `ama-upgrade-0.10.0.py` в корень работающего проекта. На вашем сервере указан путь `/opt/franch-bot`:

```bash
ssh ama
cd /opt/franch-bot
python3 ama-upgrade-0.10.0.py --check
```

Установщик принимает исходники выпущенных 0.7.0/0.8.0/0.9.0 и уже применённые новые файлы. При локальном конфликте останавливается **до записи**. `.env`, ваш Compose, Dockerfile, БД и тома он не заменяет. Обновляемые исходники резервируются в `backups/source-*`. Поддерживаются смешанные частичные обновления этих версий; более ранний или локально изменённый проект нужно сверить отдельно, не обходить проверку хешей.

Сначала сохраните действующую БД и файловый том. До установки нового журнала можно использовать привычную процедуру текущего выпуска. Пример дампа для БД `ama` (при другом имени подставьте своё):

```bash
docker compose stop api worker
umask 077
mkdir -p backups
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysqldump --single-transaction --routines --triggers --no-tablespaces -uroot ama' > backups/before-0.10.0.sql
```

Файловый том дополнительно скопируйте вашим защищённым способом. Убедитесь, что копия читается и дамп завершился без ошибки. Затем:

```bash
python3 ama-upgrade-0.10.0.py --apply
docker compose build
docker compose run --rm --no-deps migrate
docker compose up -d api worker
docker compose exec api python -m ama.cli diagnostics
docker compose exec -T api python -m ama.ops_cli preflight
```

Проверяйте результат каждой команды; при ошибке не продолжайте запуск. Не используйте `down -v`: это удаляет данные. Миграция 0010 добавляет три таблицы публикаций/эксплуатации, не переписывая прежнюю историю. С 0.7/0.8 применяются также промежуточные миграции. Старые миграции 0001–0009 сохранены. Старые файлы не становятся публичными, прежние платежи и подписи не преобразуются в фиктивные новые факты.

После запуска проверьте отправку выбранного файла на тестовом ФП, утрату прав до доставки, частичный сбой, неопределённый исход и сверку. Настройте утверждённую политику хранения. Создайте копию новым runner и проверьте её восстановление. Затем выполните живые П01–П68. Руководства: DELIVERY-0.10.0.md и OPERATIONS-0.10.0.md.

Проверка готовности ожидаемо покажет незаполненные реальные материалы, отсутствующие реквизиты/маршруты или свидетельства приёмки. Эти условия нельзя закрыть тестовыми ссылками или фиктивными отметками. Из среды разработки SSH-доступ к вашему серверу отклонён; выпуск подготовлен для установки, но на сервере не развёрнут.

Откат требует согласованной копии исходников, БД и файлов. Автоматического удаления истории публикаций/оплат/подписей через downgrade нет.
