# Обновление до 0.11.0

Обновление предназначено для исходников 0.7.0–0.10.0. На сервер оно автоматически не установлено. Для текущей установки каталог — `/opt/franch-bot`.

1. Сохраните резервную копию MySQL, файлового хранилища, исходников и `.env` вне каталога проекта. Проверьте возможность восстановления.
2. Скопируйте `ama-upgrade-0.11.0.py` на сервер. В каталоге проекта выполните `python3 /путь/ama-upgrade-0.11.0.py --check`. При конфликте локальных исходников согласуйте изменения вручную: установщик остановится до записи.
3. Остановите обработку: `docker compose stop api worker`. Примените исходники: `python3 /путь/ama-upgrade-0.11.0.py --apply`. Установщик сохраняет изменяемые исходники в резервную копию; `.env`, Compose, Dockerfile и локальные порты не заменяет.
4. Выполните `docker compose build api worker`, затем `docker compose run --rm api python -m alembic upgrade head` и `docker compose up -d api worker`.
5. Проверьте `docker compose ps`, `docker compose logs --tail=100 api worker`, `docker compose exec api python -m ama.cli diagnostics`. Проверьте /start и тестовый запрос с файлом в привязанном чате. Успех healthcheck не подтверждает доставку Telegram/MAX.

Миграция 0011 добавляет частный входящий файловый буфер, расписания отчётов, уведомления брендов и защиту банковских референсов. Старые миграции не изменены. Исторические референсы из старых долгов резервируются, без повторной проводки денег. Уже существующие дубли требуют ручной финансовой сверки; миграция не исправляет прошлые суммы. Для отката восстановите согласованную резервную копию БД/файлов/исходников: автоматический downgrade запрещён.

## Изменения эксплуатации

Старые платные предложения проходят утверждённые финансовые правила и снимок реквизитов. Неполные старые предложения нужно переоформить. Старая команда отсрочки долга заблокирована: используйте финансовый сценарий с решением руководителя. История сохраняется.

В заявке доступны изменение, файлы и пауза. `/new` предлагает продолжить незаконченный черновик. Файлы без контекста остаются частными до явного назначения; ошибка загрузки отображается отдельно, не выдаётся за доставку исполнителю.

Изменение опубликованного шаблона действует на новые планы; существующие планы сохраняют снимки. Перед публикацией проверьте роли, маршруты, зависимости, применимость и тип результата.

Для расписания отчёта заполните тип отчёта, владельца с действующей ролью, проверенный внутренний маршрут, согласование состава адресатов, календарь, начало/конец и периодичность. Утрата полномочий или изменение маршрута останавливает публикацию; причина хранится в состоянии плана. После исправления переопубликуйте настройку. Произвольный внешний адресат не допускается.

Прочитайте [исправления и ограничения](FIXES-0.11.0.md). Реальные материалы и живая приёмка остаются обязательными.
