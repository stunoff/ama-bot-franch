# Обновление 0.1.0 → 0.2.0

Обновление добавляет интерфейс сотрудников и администратора. Миграция `0002` добавляет номера версий и четыре таблицы интерфейса. Существующие люди, аккаунты, роли, привязки, работы, история и персональное ознакомление сохраняются. Схема `0001` не переписывается.

1. В каталоге работающего проекта сохраните резервную копию:

```bash
bash scripts/backup.sh "$PWD/backups/before-0.2.0"
```

Сохраните `.env` отдельно. Проверяйте резерв до обновления. Не удаляйте Docker volumes.

2. Примените файл обновления исходников из корня проекта:

```bash
python3 /путь/к/ama-upgrade-0.2.0.py --check
python3 /путь/к/ama-upgrade-0.2.0.py --apply
```

Инсталлятор проверяет контрольные суммы, сохраняет предыдущие исходники в `backups/source-…` и не трогает `.env`, `compose.yaml`, Dockerfile, файлы и БД. Если исходник изменён вручную и отличается от 0.1.0 и 0.2.0, операция прервётся до записи: сначала сопоставьте изменения. Если вместо инсталлятора используется полный ZIP, распакуйте его отдельно и перенесите исходники, сохранив свои настройки и имена volumes.

3. Соберите новый образ, остановите обработку на время миграции и запустите новую версию:

```bash
docker compose build api
docker compose stop api worker
docker compose run --rm migrate
docker compose up -d --no-deps api worker
docker compose exec api alembic current
docker compose logs --tail=100 api worker
```

`alembic current` должен показывать `0002 (head)`. При ошибке миграции сохраните вывод и устраните её до запуска api/worker. Для MySQL после прерывания DDL может потребоваться проверка частично выполненной миграции; не используйте `alembic stamp` вместо проверки.

4. Откройте `/af_settings` прежним администратором в прежнем управляющем чате/теме. Откройте `/start` назначенным куратором в сопровождении, маркетологом в маркетинге. Проверьте сохранённые работы и ознакомление, создайте тестовый черновик и убедитесь, что до подтверждения действующие данные не меняются.

Повторные `init-admin`, `seed` и регистрация webhook для этого обновления не требуются, если адрес и токены не менялись. Команда `docker compose down -v` здесь не используется.

Интерфейс описан в [CHAT_UI.md](CHAT_UI.md). Наличие новых кнопок не означает реализацию остальных пунктов плана — границы указаны в [COVERAGE.md](COVERAGE.md).
