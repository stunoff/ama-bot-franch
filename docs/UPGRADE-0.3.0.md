# Обновление 0.2.0 → 0.3.0

Сначала сделайте и проверьте резерв БД и файлов:

```bash
bash scripts/backup.sh "$PWD/backups/before-0.3.0"
```

Сохраните `.env` отдельно. Не удаляйте volumes и не меняйте образ MySQL ради установки этого обновления.

Примените установщик из каталога существующего проекта:

```bash
python3 /путь/к/ama-upgrade-0.3.0.py --check
python3 /путь/к/ama-upgrade-0.3.0.py --apply
```

Он рассчитан на исходники 0.2.0, проверяет контрольные суммы, сохраняет старые файлы и прерывается до записи при неизвестных локальных изменениях. `.env`, Compose и Dockerfile сохраняются. Если используется полный ZIP, распакуйте его отдельно и перенесите исходники, сохранив свои настройки и имена volumes. Полный комплект миграций позволяет обновить и схему 0001; повторный `init-admin` не требуется.

Затем:

```bash
docker compose build api
docker compose stop api worker
docker compose run --rm migrate
docker compose up -d --no-deps api worker
docker compose exec api alembic current
docker compose logs --tail=100 api worker
```

Ожидается `0003 (head)`. При ошибке миграции не запускайте новую версию до устранения причины; не заменяйте проверку командой `alembic stamp`. MySQL DDL после аварийного прерывания может потребовать проверки частично выполненных изменений.

Миграция создаёт интерес для каждого существующего лида, связывает прежние сделки и сохраняет платежи/даты. Ограничение одной сделки на человека заменяется ограничением одной сделки на конкретный интерес. Если старое событие постановки в очередь сохранилось в outbox, используется его реальная дата; даты без основания не придумываются. Существующий успех сделки переносится с сохранённым временем.

Обратная миграция не объединяет и не удаляет новые покупки. Для отката после записи данных используется проверенный резерв совместно с прежними исходниками; простой запуск кода 0.2 поверх новой схемы не является проверенным откатом.

Настройте продажи по [SALES-0.3.0.md](SALES-0.3.0.md): календарь, очереди, ответственные, согласие, активные бренды, утверждённые карточки/условия, источники и шаблоны. Существующие записи автоматически публичными не становятся. Имя бота можно задать в опубликованном источнике; менять Compose для этого не обязательно.

Проверьте `/start` в личной переписке и `/start` консультанта в продажах. Пройдите тестовую передачу без просмотра всех материалов, создание темы, принятие, ответ с предпросмотром, запрос Главному маркетологу и контрольную дату. Проверьте внешний `/health` через фактический HTTPS-адрес: при недоступном webhook Telegram не доставит события независимо от версии приложения.
