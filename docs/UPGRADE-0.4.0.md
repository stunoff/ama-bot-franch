# Обновление 0.3.0 → 0.4.0

Обновление исходников не выполняет действий на вашем сервере само. Сохраните `ama-upgrade-0.4.0.py` в корень существующего проекта рядом с `compose.yaml`.

Проверка не пишет файлы:

```bash
python3 ama-upgrade-0.4.0.py --check
```

При локальных изменениях обновляемых файлов скрипт остановится до записи и перечислит конфликтующие файлы. Сначала сравните их с новой версией. `.env`, `compose.yaml`, Dockerfile, тома MySQL и файлов не заменяются. Уже применённое обновление можно проверять повторно.

Остановить обработку, сохранить БД и применить исходники:

```bash
docker compose stop api worker
umask 077
mkdir -p backups
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysqldump --single-transaction --routines --triggers -uroot ama' > backups/before-0.4.0.sql
python3 ama-upgrade-0.4.0.py --apply
docker compose build
docker compose run --rm --no-deps migrate
docker compose up -d api worker
docker compose exec api python -m ama.cli diagnostics
```

Проверьте успешное завершение каждой команды. Если резервная копия или миграция завершились ошибкой, не продолжайте запуск. Не используйте `docker compose down -v`: это удалит данные. Дополнительно сохраняйте том файлов установленным у вас способом.

Миграция `0004` добавляет таблицы проектов и необязательный маршрут приёмки Work. Старые работы, деньги, роли и прогресс не переписываются; проекты из прошлых произвольных JSON-команд не превращаются автоматически в новый состав.

После запуска куратор открывает `/projects` в чате сопровождения, создаёт и подтверждает проект; менеджер открывает его из чата маркетинга. Причины ожидания видны в «Состав и ожидания». Прочитайте [PROJECTS-0.4.0](PROJECTS-0.4.0.md) перед настройкой боевого проекта.

Обновление не исправляет маршрутизацию Docker Desktop, недоступность порта хоста или webhook. Для Telegram нужен доступный снаружи HTTPS endpoint. Внутренний `/health` можно проверить отдельно:

```bash
docker compose exec -T api python -c 'import urllib.request; print(urllib.request.urlopen("http://127.0.0.1:8000/health", timeout=5).read().decode())'
```

Откат БД — восстановление проверенной резервной копии вместе с соответствующей версией исходников и файлов. Автоматического удаления проектной истории через downgrade нет.
