# Обновление 0.4.0 → 0.5.0

Сохраните `ama-upgrade-0.5.0.py` в корень работающего проекта рядом с `compose.yaml`. Сначала проверка без записи:

```bash
python3 ama-upgrade-0.5.0.py --check
```

Скрипт сверяет обновляемые файлы с 0.4.0. При локальных изменениях останавливается до записи. `.env`, Compose, Dockerfile и тома не заменяет. Старые исходники сохраняет в `backups/source-*`.

Остановите обработку, сохраните БД, затем примените исходники и миграцию. Проверяйте результат каждой команды:

```bash
docker compose stop api worker
umask 077
mkdir -p backups
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysqldump --single-transaction --routines --triggers -uroot ama' > backups/before-0.5.0.sql
python3 ama-upgrade-0.5.0.py --apply
docker compose build
docker compose run --rm --no-deps migrate
docker compose up -d api worker
docker compose exec api python -m ama.cli diagnostics
```

При ошибке резервной копии/миграции не продолжайте запуск. Файловый том дополнительно сохраняется вашим способом. Не используйте `down -v`: это удаляет данные.

Миграция `0005` добавляет `sla_cases`, `sla_events`, `sla_signals`; существующие карточки и деньги не меняет. Новые работы используют новый SLA автоматически. Старые карточки подключаются отдельно: назначенный ответственный/принимающий → карточка → «Подключить SLA» → предпросмотр → подтверждение. Исходная дата остаётся, прошлое время взятия не выдумывается.

До проверки боевых сценариев проверьте опубликованные календари, активные маршруты, роль `support_head` в управляющем чате, назначенного ФП и его клиентский маршрут. Прежние опубликованные SLA-профили должны иметь рабочий счёт и утверждённое основание. Дубли подходящих профилей требуется устранить.

Проверка после установки: обычное взятие/результат, передача приёмки сотруднику, ожидание ФП с подтверждённой доставкой, возврат, сигнал `/sla` и реакция руководителя. Подробности: [SLA-0.5.0](SLA-0.5.0.md).

Это обновление не восстанавливает сетевую маршрутизацию Docker Desktop и внешний webhook. Если бот не получает `/start`, отдельно проверяйте доступность API/ngrok. Внутреннее здоровье:

```bash
docker compose exec -T api python -c 'import urllib.request; print(urllib.request.urlopen("http://127.0.0.1:8000/health", timeout=5).read().decode())'
```

Откат — согласованная версия исходников и восстановление проверенной копии БД/файлов. Автоматического удаления истории SLA через downgrade нет.
