# Обновление 0.6.0 → 0.7.0

Сохраните `ama-upgrade-0.7.0.py` в корень работающего проекта рядом с `compose.yaml`. Сначала проверка без записи:

```bash
python3 ama-upgrade-0.7.0.py --check
```

Скрипт сверяет обновляемые файлы с 0.6.0. При локальных изменениях останавливается до записи. `.env`, Compose, Dockerfile и тома не заменяет. Старые исходники сохраняет в `backups/source-*`.

Остановите обработку, сохраните БД, затем примените исходники и миграцию. Проверяйте результат каждой команды:

```bash
docker compose stop api worker
umask 077
mkdir -p backups
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysqldump --single-transaction --routines --triggers -uroot ama' > backups/before-0.7.0.sql
python3 ama-upgrade-0.7.0.py --apply
docker compose build
docker compose run --rm --no-deps migrate
docker compose up -d api worker
docker compose exec api python -m ama.cli diagnostics
```

При ошибке резервной копии/миграции не продолжайте запуск. Файловый том дополнительно сохраняется вашим способом. Не используйте `down -v`: это удаляет данные.

Миграция `0007` добавляет `digital_programs`, `digital_facts`, `digital_steps`. Прежние работы, паспорта, доказательства технических проверок, рассылки, оплаты и SLA не конвертируются автоматически. Миграции 0001–0006 сохранены.

До первого запуска опубликуйте календари и маршруты `support`, `software`, `reviews`, при необходимости `registrations`; назначьте разных специалиста и куратора. Проверьте физическое предприятие, активные бренды, назначенного ФП и основной проверенный клиентский чат. Telegram-очереди должны поддерживать темы. Для КЦ нужен отдельный опубликованный курс `call_center` с утверждёнными карточками.

После установки: `/digital` → «Начать подготовку». Для старой digital-карточки явно выберите её в необязательном поле существующей работы. Проверьте применимость, короткие ответы ФП, предпросмотр плана, отдельные темы/результаты, возврат и приёмку, независимые мессенджеры предприятия/управления. Руководство: [DIGITAL-0.7.0.md](DIGITAL-0.7.0.md).

Это обновление не восстанавливает сетевую маршрутизацию Docker Desktop и внешний webhook. Если бот не получает `/start`, отдельно проверяйте доступность API/ngrok. Внутреннее здоровье:

```bash
docker compose exec -T api python -c 'import urllib.request; print(urllib.request.urlopen("http://127.0.0.1:8000/health", timeout=5).read().decode())'
```

Откат — согласованная версия исходников и восстановление проверенной копии БД/файлов. Автоматического удаления истории цифрового паспорта через downgrade нет.
